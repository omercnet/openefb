# M1 port notes (Israel overlays, domain side)

- Ported into `src/domain/map/israel/`: `IsraelChartFeatures.swift` (`chartFeatures.ts`, closure half in `closures.ts`), `IsraelChartDetails.swift` plus the data half of `IsraelChartOverlay.hitTest` (`chartDetails.ts`), `IsraelChartStyle.swift` palette and label/symbol kinds as data (`style.ts`), the source/layer definitions of `IsraelChartOverlay.swift` (add*Layers, applyPalette, applyOfficial), `IsraelLSAOverlay.swift`, `IsraelOfficialChartLayer.swift` and `IsraelBriefingMapHighlight.swift` (`layers.ts`, `briefing.ts`), and `IsraelChartData.load` (`loadIsraelChartInput`).
- Tests. `ServiceTests/IsraelChartFeaturesTests.swift` (38): 37 ported, 1 moved, 0 dropped. Moved: `switchingToIsraelShowsTheChartAndBackToTheUSDropsIt` tests `AppState.visibleLayers` (whoever ports AppState). The two other availability cases test core (`regionSupports`, `isLayerAvailable`, `isCvfrChartLayer`) and are ported here as written. `ServiceTests/IsraelBriefingFilterTests.swift`: the one `IsraelBriefingGeometry` case is ported here (L3b moved it to M1); the other 19 cases are L3's. JS-only extras: 6 (highlight source and bounds, registry validity and night paints, official-chart overrides and mbtiles URL, source keys and features, tap selection). Total 44, all green.
- Closures: the NOTAM closure mapper and feed types are L3's. `israelClosureSet(report, matches, now)` takes the mapper's output (`IsraelClosureMatchInput`, segments by id) and `{ generatedAt }`; freshness is `evaluateFreshness('notam', ...)`. Swift filtered CVFR closures before mapping; here the filter runs on the matches (the mapper maps each closure independently, so same result). JS-only guard: matches outside their validity window at `now` are dropped again (a no-op on mapper output). The closure test cases run through L3's real `mapClosures` (with a test lookup over the test network). `IsraelChartNetwork` is not ported here: L3's `IsraelNetworkLookup` is that port.
- Structural input types (`IsraelRouteClosureInput`, `IsraelAltitudeLimitInput`, `IsraelBriefingNotamInput`) are subsets of L3's `notamTypes`; L3 types are assignable. `closureSeverity`, `closureCovers` and `altitudeChartText` duplicate L3 helpers; dedupe when L3 merges. L3's `l3bStandIns.ts` (`IsraelChartClosureMark`, `limitText`, `limitsText`) should be replaced by these exports.
- Sprites become text: Swift drew every label to a UIKit sprite so the chart drew with no connectivity. Labels are now `text-field` symbol layouts in 'Noto Sans Regular', the only `text-font` in `assets/base-style.json` (verified). That style's glyphs URL is openfreemap over the network, so offline the CVFR labels (altitudes, point codes, airspace limits, and the closure "CLSD" text) do not render; the closure casing lines still do. This is a safety regression against Swift unless glyphs are bundled. Open question: are U+2192/U+2190 (altitude direction arrows) in the served Noto Sans Regular ranges? Needs an on-device check.
- Label styling: Swift used the system semibold font with a stroke halo of about 7% of the point size; now Noto Sans Regular with a 1.5 px halo. Swift icon offsets in points became `text-offset` in ems (point labels 9/11, closure labels -13/12). Collision flags map 1:1 (`icon-allow-overlap` -> `text-allow-overlap`, padding, ignore-placement).
- Point symbols: Swift triangles and rings were sprites; here they are circle layers keyed on the feature `symbol` property: compulsory filled, on-request hollow, aerodrome 5.5 px ring, airstrip 4 px ring, heliport 6 px ring. Lost: triangle shape, aerodrome ring ticks, the heliport "H", the halo under symbols. If Q1 fidelity needs them, register images and switch these three layers back to `icon-image`.
- Palette: hex from the Swift UIColor components rounded to 8 bits. Night `systemOrange` and `systemRed` are resolved to their dark variants (#FF9F0A at 0.85, #FF453A); Swift's dynamic colours resolved by trait, which was not verified for night mode.
- Layer gating: every chart spec carries the toggle from `IsraelChartOverlay.ID.all`; LSA specs use `lsaRoutes`. Deviation from the contract: the briefing highlight specs have `layer: null`, because Swift drew them regardless of any toggle. Swift showed the LSA network when the toggle is on OR the plan uses LSA; the spec only expresses the toggle, so the surface must force it on for an LSA plan.
- Official chart: `ISRAEL_OFFICIAL_CHART_LAYER` (raster, `layer: null`, night = `NIGHT_RASTER`) is not in `ISRAEL_LAYER_SPECS`: Swift inserts it above the street base and below every flight layer, and it is not toggle-gated. `israelOfficialChartUrl` reproduces the `mbtiles://` percent-encoding. `applyOfficial` became `israelOfficialChartOverrides(present, visible, night)` (forced visibility and paint per layer id) that the surface merges.
- Draw order: Swift insertion order (airspace, runways, aerodromes, routes, closures, points), then LSA and briefing. Swift inserted chart layers below `ownship-symbol` but added LSA and the briefing highlight on top of the whole style (above ownship). Placing the registry relative to ownship is the surface's call.
- GeoJSON: rings are closed explicitly (MapLibre native closed them). Airspace holes with fewer than 3 points are dropped and outer rings with fewer than 3 are skipped, as Swift. Swift features had no ids; properties carry what the layers and hit test read.
- Hit test: only the data half is ported (`israelSelectionFromFeature`, `israelAirspaceSelection`). Finding the nearest point/aerodrome icon within 26 pt and the fills under the tap is the surface's job. The ARP-with-aerodrome check skips foreign aerodromes, which matches `IsraelChartData.load` dropping them.
- Briefing: colour is a feature property (Swift recoloured the layers on each call). `israelBriefingBounds` returns the box; Swift framed it with 100 pt padding.
- Swift behaviour kept: `IsraelAirspaceDetail.rawText` is the label for every kind, though the doc says TMA only. Unlisted points get an icon (in the non-request icon layer, on-request symbol) but no label layer. An empty-string airspace code counts as present in titles. `circleRing` is flat-earth degrees. The Q-line circle is used only under 100 NM. The briefing fill layer has no filter, so it also gets line features (no effect), and the line layer outlines the polygons.
- Not ported (left): the closure refresh loop (`fetchInterval` 300 s, `tick`, applied-key change detection) and NOTAM fetching (S1/UI hook); install/uninstall, display-mode switching and visibility application (surface, using `nightPaint` and the overrides); offline glyphs; sprite fidelity for symbols if needed.
- Non-test code: 1536 lines (1256 excluding blank and comment lines), against a budget of about 1200. Per the coordinator's correction, only `npx jest src/domain/map/israel` was run; tsc and eslint were not run on these files.

## Review follow-ups (#52)

- Layer order: the Israel layers sit below the track ruler, route and ownship (Swift `IsraelChartOverlay.place` inserts below
  `ownship-symbol`; `raiseRouteLayer` lifts the route and ruler back above). The LSA and briefing overlays used `addLayer` in
  Swift (on top), but they are drawn with the rest of the Israel set here; ownship and route stay above all of them, which
  is the safety-relevant part. Splitting LSA/briefing back above the core layers is a one-line registry change if a capture
  shows it matters.
- KNOWN REGRESSION, deferred: labels are `text-field` layers using the base style's glyph endpoint, so offline they vanish
  while geometry still draws (Swift rendered labels to local sprites). The fix is a bundled glyph pack (Noto Sans PBF ranges
  referenced from `glyphs` in base-style.json, also used by the street layer and offline packs), which is an asset and
  base-style change shared with the whole map, not an Israel-only edit. Tracked for the offline follow-up (M3 downloads the
  street pack with glyphs, so labels work offline once a street pack is downloaded).
