# U4: Nearest and Search columns (U4a)

Part a of U4: the Nearest and Search strip columns with their view models. The weather and briefing sheets, the Israel
flight plan and the airport sections (NOTAM, PIREPs, winds aloft, diagrams, Israel aerodromes) are part b (U4b), a later PR.
Screens read their data through hooks over Zustand slices with fakes behind them (`src/ui/state/storeContext.tsx`); the real
services are wired by I1.

## Swift differences

- Async + request token (JS-only): Swift queries synchronously. Only the latest refresh / search may write; a fix that
  arrives while a query for a spot within 0.5 NM is in flight sends no second query.
- Errors (JS-only): Swift keeps stale entries silently. Here the entries are kept too, and `error` (message) is set;
  the column shows "Could not refresh: showing the last list" over the list, or "Nearest airports unavailable" when
  there is no list. The raw error text stays in the store, not in the UI. A failed refresh does not count for the move
  threshold, so the next fix retries.
- Loading (JS-only): with no list yet and a query in flight the column shows a spinner instead of "No landable airport in
  range" (Swift has no visible loading state; its query is synchronous).
- Search failure: Swift clears results silently (kept), and the column would then say "No airports match"; here a
  `failed` flag shows "Search is unavailable right now" instead. Israel with no aerodrome database counts as a failure.
- Search guard (JS-only safety guard): a query with no letter or digit is never sent. In the US this changes nothing
  (the FTS query answers nothing for punctuation); in Israel the Swift sends it to the LIKE search, and bundled names
  contain '/', '(' and '-', so the Swift lists results for " /" where this lists none. Length check: Swift
  `query.count` counts grapheme clusters; Intl.Segmenter where the engine has it, else code points minus combining marks.
  "No airports match" uses the same predicate (`isSearchableQuery`) on the trimmed query, so it never shows for a query
  that was not sent (a single emoji, a Hebrew letter with a vowel mark).
- Search state persists: as in the Swift (SearchViewModel is @State on MapContainerView), the query and results stay
  when the Search column is closed and reopened, and a search typed just before closing still runs; only picking a
  result clears them. The state is the `searchSlice` store, with one controller (debounce, request token) per store;
  `resetSearch(store?)` empties a store and cancels its pending search (tests reset the default store). New databases
  in AirportQueriesContext re-run the current query on them (an answer from the old ones is dropped, a failure they
  caused is cleared).
- Keyboard: the strip handles the software keyboard with padding on both platforms (StripColumn; Expo is edge-to-edge
  on Android, so the window does not resize).
- Israel MHz parsing: Swift's `Double(mhz)` also accepts hex floats, "inf" and "nan"; the TS check accepts plain decimals
  only. All 68 bundled values are plain decimals, so both agree on the shipped data.
- Caution tags: ViewThatFits is reproduced by measuring the tags in a hidden copy with no width cap (a 10,000 pt row in
  a zero-size clipped box, out of the accessibility tree), so each width is the natural one even when wider than the
  column, and comparing their sum plus the 8 pt gaps with the width the row gives them: one line when they fit, else
  one per line (never the 2 + 1 a flex wrap would pack). Nothing is shown until both are measured, also after the tag
  set changes, so no guessed layout is painted (the tags appear one layout pass after the row). Each visible tag has
  minWidth = its natural width, so like .lineLimit(1).fixedSize() it overflows rather than wrapping ("NOTAM / CLSD").
  The ident sits in a row of its own with flexShrink 0, so it keeps its natural width on the horizontal axis and
  overflows rather than wraps (idents are at most 7 characters).
- Israel database provider: Swift throws from `IsraelAviationDatabase.bundled()`; here a null `israel` source reads as a
  failed query (same effect: stale list kept).
- Number formatting: `%.1f` and `%03.0f` use the strip's `printfFixed` (`flightLog/logic.ts`: C printf rounding, an exact
  binary tie goes to even, read from the exact decimal expansion), including the Swift's "360\u00B0" for bearings >= 359.5
  (preserved). The column first had its own copy of that function, which read a tie from a floating-point multiply (0.35 *
  10 is exactly 3.5, so 0.35 printed "0.4" where C prints "0.3"); an independent review found it and the copy is gone.
  The row's runway length is grouped ("2,441") because SwiftUI Text interpolation localises Ints; `runwaySummary` (String
  interpolation, for the HUD) is not.
- Distance: domain distanceNm (haversine, R = 3440.065 NM) instead of CLLocation's ellipsoidal distance; up to ~0.5%
  apart. FIXTURE_OWNSHIP (37.47578, -122.15374) was found by search so every reference row prints exactly.
- israelFrequency id: Swift makes a fresh UUID per mapping; here `<code>-<row id>` (stable list key).

## Review decisions

- The runway line renders with a non-breaking space between length and surface: iOS's line breaking pushes a would-be
  orphan word down ("10R/28L" / "5,694' ASPH" in the reference), which RN does not; the accessibility label keeps plain
  spaces.
- Direct button: 74 pt capsule (60 pt label frame + borderedProminent's 7 pt), 12 + 12 pt side insets; measured 102-103
  x 73-74 on web vs 103 x 73 in the reference.
- The refresher is kept per store (WeakMap), so several mounted callers share the threshold and the token.
  AirportQueriesContext values are compared field by field (`sameQueries`: aviation, israel, fetchNotamClosures, now),
  not by object identity: other sources are a database swap (`setQueries` bumps the token so an answer from the old
  queries is dropped, forgets the threshold and the NOTAM feed, and the hook requeries; the search re-runs its query),
  while a fresh object around the same sources (an inline provider value) changes nothing. Memoising the value still
  saves the hooks' effects.
- StatusTag uses black text on the day caution fill (`Color.black`; no token covers it).
- `onAirportTap` / `onSelect` default to `appStore.showAirport`; `onDirectTo` defaults to the store's `directTo`.

  first CI capture of `search` shows whether the footer lands where the reference has it.

## Planned deviation for U4b: the Israel flight plan e-mail goes to the IAA

The Swift app addresses the Israel flight plan draft to the pilot's own e-mail address
(`IsraelFlightPlanViewModel.swift` `mailURL(to:)`: `components.path = address ?? pilotProfile?.email ?? ""`; the doc comment
says the pilot forwards it to the filing address himself). That is a bug (https://github.com/omercnet/openefb/issues/39):
`IsraelFlightPlanMessage.filingAddress` is `ais@iaa.gov.il` and the screen's help text already names it. The React Native port
(U4b, `Views/Planning/IsraelFlightPlanView.swift` and `ViewModels/IsraelFlightPlanViewModel.swift`) addresses the draft to
`ais@iaa.gov.il` from the start and does not port the pilot-address default. The app still only opens the draft; the pilot taps
Send. Whether the pilot's own address goes in Cc (the issue suggests it as optional) is decided in the U4b PR. The U4b notes
and PR body repeat this with the same link.
