# U1: tokens, primitives, display mode

## Ported

- `Core/DisplayMode.swift` -> `src/domain/displayMode.ts` (pure, platform-free: `DisplayMode`, `DisplayModeResolver`,
  `SolarPosition`). `DisplayModeResolverTests` (8) -> `src/domain/displayMode.test.ts`, same names and inputs.
- `Views/Map/DisplayModeModifier.swift` scheme decision -> `colorSchemeFor` in the same file (2 extra cases).
  The 60 s clock and the preferred-colour-scheme plumbing belong to the screen that mounts it.
- `Core/DesignTokens.swift`: audited against `src/ui/tokens.ts`. Space, Radius, StripMetrics and the strip palette were
  already exact; added the missing `Palette` entries (onWarning, cautionFill, northMarker, fill, routeLine, infoFill,
  categoryLIFR, layer tints, accent high contrast) and `MapControlMetrics`. `src/ui/tokens.test.ts` reads the Swift
  file in place and asserts parity (no Swift test covers the tokens).
- `Views/Components/*` (7) -> `src/ui/components/Components.tsx`; their decisions (status words and colours, alert
  levels, category colours, percent text) are in `components/logic.ts` with `logic.test.ts`.
- Icons added: xmark, xmark.circle.fill, info.circle, exclamationmark.octagon.fill.
- Accessibility roles: badges are single accessible elements with a spoken label and value; the DB banner is
  role `alert`; the slider is `adjustable` with increment/decrement actions; dismiss and clear buttons are labelled
  buttons with 44/60 pt targets; decorative icons are hidden.

## Not ported

- `MapQueryRegionTests` (17): maps to `Services/MapQueryRegion.swift`, ticket M1, not U1 (the port-map lists it
  under DesignTokens only because the tests touch `Region`).
- `Core/Interaction.swift`: `PressableButtonStyle` is `Pressy` (already matches 0.55 / 0.97). `Haptics` is a platform
  adapter, not in U1's owned files; left for a ticket that adds an expo-haptics adapter.
- `MapColor` (UIColor.system* values for map layers): resolved per theme where the map code uses them.
- No component render tests: the repo has no react-test-renderer / testing-library; adding either is a shared
  package.json change. Logic is tested as pure functions instead.

## Swift differences

- `Palette.fill` (`Color.secondary.opacity(0.12)`) is 0.12 x the 0.6 secondary alpha = 0.072, expressed as rgba.
- RN has no system slider: `OpacitySlider` draws its own track and knob (no dependency added).
- Components take plain props instead of reading AppState / RemoteConfigStore, and `DataAgeBadge` takes an evaluated
  freshness (level, text, product name) rather than a model type from a later ticket.

## Review decisions

- `colorSchemeFor` with an invalid coordinate returns 'light': Swift `DisplayModeModifier` calls `isNight(systemIsDark: false)`, which for an invalid coordinate is false. Preserved (Swift parity).
- Airport `Row` fixed height (U2): kept; the column's values are short fixed-format strings and the strip does not scale with Dynamic Type; the height is what removes the 0.5 pt/row drift.
