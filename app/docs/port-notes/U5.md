# U5: the iPhone rail layout

The compact half of the map screen: the layout Swift shows on an iPhone, in a narrow iPad Split View pane, and at any
width while Layers > Panels > Flight log is off. Builds on the U3 strip pieces; screens still read their data through
the U3 hooks and fakes, and I1 mounts the screen.

## Ported

- `Views/Map/MapContainerView.swift` `compactLayout` + `compactChartArea` -> `src/ui/CompactMapLayout.tsx`: header and
  warnings on top, the NEXT rail and a 1 pt rule beside the chart while the flight log is shown, the NOW cell at full
  width while the instruments are shown, then the footer. An opened column (airport, nearest, layers, search) covers the
  area above the NOW cell and the chart stays mounted under it; NOW and the footer stay. With the instruments hidden
  Clear moves to the header (`headerClear`).
- The layout switch (`horizontalSizeClass == .compact || !showsFlightLog`) -> `src/ui/layout.ts` (`widthClass`,
  `usesCompactLayout`, `useWidthClass`) and `src/ui/screens/MapScreen.tsx`, which picks the 400 pt strip
  (`regularLayout`) or the compact layout. The palette, font readiness and safe-area insets both layouts need moved
  from `StripColumn` into `useStripChrome` (`src/ui/StripColumn.tsx`), and the column table is exported as
  `STRIP_COLUMNS`.
- `Views/Log/FlightLogStrip.swift` `FlightLogRail` -> `FlightLogRail` in `src/ui/flightLog/FlightLogStrip.tsx` (a
  104 pt `ScrollView` labelled "Flight log").
- The `compact:` variants:
  - `FlightLogNext(compact:)` -> `FlightLogNext({ compact })`: 2 later rows instead of 3, no section detail (direct,
    route, plan), 8 pt padding; the next row stacks the ident over the time-to in row sizes (28 / 44 pt, shrinking to
    0.5) and the predicted-event block stacks what is met (two lines) over the time; later rows stack ident and data
    line over the time.
  - `FlightLogNowCell(compact:)` -> `FlightLogNowCell({ compact })`: 8 pt padding, 38 pt readouts. As in Swift the
    compact layout draws the cell without the NOW band.
  - `FlightLogFooter(compact:)` -> `FlightLogFooter({ compact })`: the GPS cell is at most 76 pt (NRST takes the rest of
    the window) and wraps onto two lines (`lineLimit(2)`).
  - `FlightLogHeader(compact:)` / `RecordButton(compact:)` -> the `compact` props: the record control shows its glyph
    only, without the level meter and the elapsed time; the time is still in its spoken value. The header is compact
    only on a compact window, not on an iPad with the flight log hidden.

## Not ported

- `ContentView.swift` (listed under U5 in the port map): the database and remote-config banners, the log stack over the
  always-mounted map, telemetry and the remote-config refresh need the Log screen (U7), the remote config store (S1) and
  app startup and navigation (I1). The map screen is still mounted from the spike routes.
- Fidelity gate: no iPhone screen is registered. The Swift references (`iphone-*.png` from `tools/ci/capture-screens.sh`)
  are only in CI artifacts, and the RN capture scripts boot an iPad and a tablet emulator only; adding an iPhone
  simulator and a phone emulator to both capture jobs is a CI change for its own PR.
- Banners owned elsewhere are as in U3: the compact layout draws `FlightLogNotices` under the header, so every notice the
  strip shows appears there too.

## Swift differences

- Size class: React Native has no horizontal size class, so `layout.ts` derives it from the device class, not the window
  width (owner decision): an iPhone is compact in portrait and in landscape, except the Plus and Max models, whose landscape
  UIKit reports REGULAR (mirrored: landscape with a shorter side of 414 pt or more, i.e. portrait widths 414, 428, 430 and
  440 pt, gets the strip layout; the 375 to 402 pt iPhones stay compact in landscape, like Swift). The 414 pt boundary is
  from Apple's published size-class table and is not verified on a device here. An Android phone (smallest screen width
  under 600 dp, which rotation does not change) is always compact. Tablets and the web preview follow the window width
  (under 600 pt compact: half of an 11" iPad in landscape, 590 pt, is compact; half of a 13" iPad, 678 pt, is regular).
  Flight log off forces the compact layout at any size, as in Swift. Rotating a phone no longer remounts the map.
- Switching layouts (a tablet Split View resize across 600 pt, or the Flight log toggle) remounts the chart, because it sits
  in a different place in each tree. Swift's `MapService` keeps the same `MLNMapView`; here the camera state the map
  needs to come back where it was is I1's (the footer store already holds zoom and following).
- Covered views leave the accessibility tree: while a column covers the header, rail and chart they are marked
  `accessibilityElementsHidden` / `importantForAccessibility="no-hide-descendants"`, so VoiceOver and TalkBack cannot
  reach controls the pilot cannot see. SwiftUI's `ZStack` does not do this by itself.
- The compact GPS label is wrapped in code (`monoWrapFit` in `footerLogic.ts`: greedy word wrap of the monospaced face,
  then the largest scale at which two lines fit, floor 0.7, then tail truncation), and drawn as explicit lines, so iOS,
  Android and web cannot break it differently. "GPS 3D", "GPS DEGR" and "GPS LOST" wrap at 15 pt; "GPS LOST 14 S" does
  not fit two lines even at 0.7 and, as in SwiftUI, the second line is cut: "GPS / LOST 1...". Kept for parity; flagged for
  the Swift owner (the fix age is lost on the iPhone footer, though the spoken label keeps it).
