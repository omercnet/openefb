## R6: layers are data

MapLibre RN v11 has no imperative `addLayer`/`setSourceData`; sources and layers are native components. The registry
(`domain/map/layers.ts`; the Israel registry joins it in the next PR) holds every layer as a plain `LayerSpec`; the surface
renders it with one loop (`groupBySource`), one `GeoJSONSource` per source with its layers nested, so the number of React
children is fixed (10 sources, 16 layers for the core set) however many airports, airspaces or TFRs are loaded. Data
changes only replace the `data` prop of a source. `validateRegistry` enforces unique ids, known sources and contiguous
specs per source (nesting preserves z-order). Visibility is the `layout.visibility` of each layer, derived from the
layer set and region (`isLayerVisible`), so toggling never re-creates a layer. A Q3 perf budget measurement is not part of
this PR (needs a device run).

## Swift behaviour preserved on purpose

- Weather dots are all green (Swift TODO: data-driven category colours). The `flightCategory` attribute is in the data.
- Airspace fill/border are one blue for every class (Swift TODO).
- `priorityRank` uses `^[A-Z]{4}$`; Swift used `Character.isLetter && isUppercase`, which also accepts non-ASCII
  letters. ICAO ids are ASCII, so the result is the same for real data.
- `loadAirports` leaves the previous airports in place on a database error and sets `databaseCorrupted` (Swift identical).
- `regionDidChange` clears layers the region lacks, but airports for a region without airport data are cleared via the
  normal load path, as in Swift.
- Layer order follows `MapService.onStyleLoaded`: ownship sits below the airport dots; advisories and the ruler sit
  below ownship. (The Q1 spike drew the ownship on top; the scenario capture has no overlap.)
- Track ruler minutes are 1, 2, 3, 5, 10 (Swift). The scenario capture passes 1, 2, 3, 5 to match the reference image.

## JS-only guards and deviations (none changes a Swift expectation)

- Async: the TS database is async, so loads return promises. Each source load carries a latest-wins token; a slower,
  older load never overwrites a newer one. Airport loading is counted (`isLoadingAirports` is true while any is in
  flight and never sticks after an error). Weather waits for the airport load of the same pass (Swift loaded airports
  synchronously first); without that the stations list is empty.
- `lastQuery*` are recorded before the awaited load, so a second region change cannot slip past the requery check.
- `settleRegionChange` resolves when the last pending change has run; `dispose()` cancels the timer and settles waiters;
  `activate()` re-arms it for React strict mode.
- Polygon rings are closed explicitly (GeoJSON requires it; MapLibre native closed them implicitly) and points with
  non-finite values are dropped. A non-finite track or ground speed clears the ruler; a non-finite heading draws north.
- Gesture kind: MapLibre RN reports one `userInteraction` flag, not pan vs pinch. `gestureSuspendsFollow` infers a pan
  (centre moved more than 2% of the visible span) or a rotation (more than 1 degree). Zoom-only gestures keep follow.
- `AviationAdvisory` is not ported yet (no ticket owns it in this track); `MapAdvisory` is a structural stand-in with
  `validFrom`/`validTo` epoch ms and the colour already resolved. Replace with the real type when it lands.
- The data controller is a plain class with `subscribe`/`getSnapshot` (React `useSyncExternalStore`) and takes `MapAppState`
  (region, visible layers, centre, zoom, bounds) as a mutable object; I1 backs it with the app store.

## Fidelity (Q1)

New capture state: `kanaf-dev://map-layers` (`src/app/map-layers.tsx`) renders the map with every data layer on (airspace,
navaids, TFR, AIRMET, weather, route) from `fixtures/mapLayers.ts`. It is added to the Android and iOS capture scripts'
default screen lists, so the screenshot is produced and uploaded in CI. It has no SwiftUI reference image yet (the
reference must be captured from the Swift app on a macOS runner), so `compare.mjs` skips it and no threshold is
registered: a threshold without a reference reads MISSING and fails the gate. When the reference lands, add
`map-layers` to `scripts/fidelity-thresholds.json` (android 0.85 map, iOS per config). The existing `map` and `night`
captures now run through the production surface and must stay above their floors; this is the first CI run that checks it.

## Review follow-ups (CodeRabbit on #44)

- Kept as Swift parity: the first in-region fix always jumps the camera to the aircraft, even if the pilot panned before it
  (`MapViewModel.onOwnshipUpdated` checks `hasCenteredOnFirstFix` before `followState.isFollowing`). The pan still suspends
  follow for later fixes.
- Fixed (JS-only): a style reload after a pan reloads the current view instead of the region home view; a region switch
  cancels a queued view change; `settleRegionChange` waits for every in-flight run; overlays redraw when an item expires inside
  the same age class; closed rings need four positions; coincident route endpoints and non-finite ground speed draw nothing.

  render probe repeats (up to 15 s) until airport dots were placed before reporting the map ready.
