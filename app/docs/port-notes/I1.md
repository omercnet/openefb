# I1: app wiring (I1a startup and map, I1b sheets and planning, I1c recording and log)

One app state that connects the ported services to the screens so the production app runs on live data. The Swift
reference is `efb_212App.swift`, `ContentView.swift`, `Views/Map/MapContainerView.swift` (`initializeServices` and its
`onChange` handlers), `Core/AppState.swift` with `AppState+Navigation.swift`, and the view models.

## Survey (written before I1a's code)

### Startup order

Swift (`efb_212App.init`, `ContentView`, `MapContainerView.initializeServices`):

1. `EFBModelContainer.makeForApp()`: the SwiftData store with its migration plan. If the store cannot be opened it is
   left untouched and the app runs on an in-memory store (logged, no banner).
2. `Telemetry.start(region:)` with the saved region (I1c wires telemetry).
3. Onboarding until `hasSeenOnboarding`, else `ContentView`: `DatabaseUnavailableBanner`, `RemoteConfigBanner`, then the
   always-mounted map (`MapContainerView`) with the log stack over it.
4. `ContentView.task`: `RemoteConfigStore.refreshIfDue(recordingActive:)`, again on every return to the foreground and
   when a recording ends (at most hourly, never while recording).
5. `MapContainerView.onAppear` -> `initializeServices`: saved region (`RegionStore.load`), the aviation database
   (`AppState.getOrCreateDatabaseService`: on failure `databaseError` is set, the queries throw and the red banner shows),
   `MapViewModel` with weather, TFR, AIR/SIGMET and proximity services, Israel alerts, `LocationService.startTracking`
   (CoreLocation prompts for When In Use on the first `liveUpdates`), `NearestAirportViewModel`, `SearchViewModel`,
   `ReachabilityService.start` (`appState.networkAvailable`), then the recording services.
6. Per fix (`onChange(of: ownshipPosition)`): nearest refresh (0.5 NM throttle), ownship on the map, proximity and
   Israel alerts, the first-fix camera jump inside the region. Per fix in `LocationService`:
   `AppState.updateActiveRouteProgress` (Direct-To, Israel route, US plan destination).

The RN plan (section 7, brief I1a) keeps this order with the async steps explicit: user database open and schema
migrations, aviation databases, remote config (saved copy loaded, the network check started), data refresh, then UI.

## What I1a does

- `ui/shell/startup.ts` (`runStartup`) is the launch sequence: user database and migrations (in-memory fallback, logged,
  no banner, as Swift `makeForApp`), saved region, aviation database (failure -> `databaseError`, the red banner), Israel
  database (failure -> Israel queries fail, as Swift `try?`), remote config saved copy. `ui/shell/runtime.ts` builds the
  services from the adapters and is imported only by the live route; `LiveAppGate` shows paper until it is done.
- `ui/shell/LiveApp.tsx` is ContentView: the two banners over the map, and the connections below.
  `remoteConfigChecks.ts` is `checkRemoteConfig` (launch, app active, recording ended; the store limits it to hourly and
  never while recording). `banners.ts` is `RemoteConfigBanner.items`.
- `ui/shell/liveData.ts`: location service -> ownship (map), GPS status (re-evaluated every second so a 5 s old fix turns
  stale without a new update), the NOW readouts, nearest `ownship`; network -> `isOffline`; `AppState.updateActiveRouteProgress`
  on every fix; Direct-To (`domain/route/navigation.ts`, the port of `AppState+Navigation.swift`) from the Nearest and
  airport columns, Clear and the route sequencing buttons.
- `ui/screens/MapScreen.tsx` is the live map: aviation database, weather, TFR and AIR/SIGMET services, the real region
  and its home view, `ownshipInRegion`, the route line for the active navigation, `useNearestAirports` mounted once,
  footer zoom/following from the camera (`zoomTo` is a new camera action), periodic data refresh
  (`ui/map/refreshDue.ts` = `MapViewModel.refreshDueData`, once a minute).
- `ui/shell/layersFeed.ts`: the Layers column's layer switches drive the controller and its fetch times feed the
  column. `ui/shell/airportColumnLoader.ts`: airport and METAR/TAF for the selected airport (`WeatherViewModel`).
- `adapters/network.ts`: `@react-native-community/netinfo` behind `NetworkStatusSource`, with a fake. Only an explicit
  "not connected" is offline (`NWPathMonitor` status != satisfied).
- Slice defaults are empty/live. The fixtures reach the capture routes through `ui/capture/seeds.ts`
  (`applyCaptureSeeds`, run by `MapCaptureScreen` before its first render); `ui/capture/MapCaptureScreen.tsx` is the old
  fixture `MapScreen` unchanged in behaviour, so the screenshots compare the same screens.
- ESLint (`eslint.config.js`): production files may not import `fixtures`, `fixture`, `*Fixtures`, `capture*` or
  `ui/capture/*`. The remaining importers are listed in `SAMPLE_DATA_UNTIL_I1B_I1C` (an entry is a to-do).

## Deviations from Swift

- Region default: `parseRegion(null)` is Israel (`DEFAULT_REGION`), as ported earlier; a fresh install therefore opens on
  Israel until Settings stores a region. Not changed here.
- Low Power Mode: the refresh scheduler gets `lowPower: false` (Swift reads `ProcessInfo.isLowPowerModeEnabled`). No
  low-power API is in the dependencies; add `expo-battery` or a native shim with the device checks (I3).
- Airport column charts: `charts` reads `failed` ("not available in this build yet") until I1b wires
  `AirportChartsSection`; `notamKeyConfigured` is false for the same reason. This is a stub, not a Swift behaviour.
- JS-only: the GPS status and `nowMs` tick once a second in `liveData` (Swift redraws on its own timers).

## Review follow-ups (PR #68)

- Fixed: the refresh scheduler read copied timestamps and so recorded every TFR/AIRMET refresh as failed (doubling its
  interval); it now reads the controller live (`refreshableMapFor`). A refresh tick no longer starts while the previous
  run is pending. The airport column loader ignores an older weather load that finishes after a newer one, keeps the
  report on screen when a refresh fails (the cache is cleared first), remembers a failed airport lookup so the refresh
  button retries it, and writes nothing after it is stopped. The chart cycle in the Layers slice follows the clock.
- Kept as Swift (parity, not fixed): `sequenceActiveRoute` without a fix keeps the previous leg's bearing and ETE
  (`AppState+Navigation.swift:85-95` sets only `distanceToNext`), and a manual back leg is undone by the progress
  refresh when ownship is already past that leg's end (the refresh always runs and auto-sequences). Both are Swift
  behaviour; the owner rule is parity.
- Kept as Swift: the Layers chart-cycle badge uses the calendar sectional cycle (`chartExpirationDate` is
  `SectionalCycle.current(at: now).expires`, `MapViewModel.swift:82`), not the cycle of the displayed chart.
- Layers persistence: only the display mode is saved (Swift UserDefaults, `AppState.swift:75-77`); orientation and sectional opacity reset to north up and 70% each launch, as in Swift. The settings row's `defaultMapMode`/`sectionalOpacity` are not written (Swift only writes them from the debug seed hook).

## What I1c does

- **Recording** (`ui/shell/recordingRuntime.ts`, `recordingBinding.ts`): the real `RecordingCoordinator`,
  `FlightPersistenceService` and `FlightRecoveryService` on the recording database (`recording.sqlite`), the audio recorder,
  the speech transcription and a location-backed track recorder (`domain/recording/trackRecorderAdapter.ts`). The strip's
  record control, the stop dialog and the notices run on it; recordings left by a crash are recovered at launch once the
  profiles are loaded (the one in progress is never touched); the auto-start monitor runs (15 kt, on, as in Swift). A

- **Log screen** (`LiveScreens.tsx`, `logFeed.ts`): the Log over the map (the map stays mounted), flights and entries from the
  user database, add / open / delete entries (a signed entry is never deleted), the entry editor, and the recorded flight:
  detail with its CVFR debrief, the AI debrief, and the replay (`LiveFlight.tsx`, `flightScreens.ts`). Screens over the map
  follow the display mode.
- **Israel flight plan** from Plan a flight in the Israel region (`israelPlanner.ts`, `LivePlanner.tsx`): the plan activates
  into the app store's navigation (strip, route line), Brief opens the NOTAM briefing for the planned route.
- **Airport column**: the FAA NOTAM list (`notamSection.tsx`, all NotamSection states) and the Israeli aerodrome section
  (`israelAerodromeSection.tsx`, which replaces the generic runways).
- **Launch**: onboarding until "I understand" (`hasSeenOnboarding`), the speech model is fetched, the background location
  task is defined at bundle load (`adapters/locationTaskRegistration`), usage counters (`App.launched`, `Navigation.screen`,
  `Israel.briefingOpened`, `Recording.*`, `FlightPlan.activated`, `Debrief.generated`) are counted and sent only when
  `EXPO_PUBLIC_TELEMETRY_URL` is set.
- **OTA guardrails** (plan 6.3): `checkAutomatically: ON_LOAD` with `fallbackToCacheTimeout: 0` (download at launch, run
  from the next cold start; the CI smoke build keeps `NEVER`), `domain/updates/reloadGuard.ts` (the one reload path, the OTA
  smoke screen, refuses while a recording is active), and a test that nothing else calls `reloadAsync`. No publish channel
  is configured.
- **Low Power Mode** from `expo-battery` (new package, SDK 58 version) doubles the data refresh intervals.
- **Diagrams switch**: persisted like Swift (`showAirportDiagrams`, default on).

## What to check on a device (I3)

1. **First launch**: onboarding shows once; location prompt on the first fix; the map opens on the saved region (Israel on a
   fresh install), then the aviation data and the Israel chart draw.
2. **Location**: background tracking continues with the screen off during a recording; the GPS chip goes stale after 5 s
   without a fix; Wi-Fi-only iPad shows the "no GPS" state.
3. **Recording**: microphone prompt and the denied state; a recording survives a phone call and a route change (gap notice);
   stop with and without a track (saved vs discarded); a force-quit during a recording is recovered at the next launch with
   the right times; the file lands under Application Support and replays.
4. **Replay and debrief**: the replay follows the track with audio; the AI debrief on a device with Apple Intelligence (and
   the unavailable states); Android shows no AI debrief.
5. **Storage**: the recording and user databases and the NOTAM, chart and diagram caches are restored after a relaunch;
   secure storage keeps the FAA NOTAM key; the speech model download on a fresh install.
6. **Network**: offline badge on airplane mode; weather, TFR and AIRMET refresh and Low Power Mode intervals; the NOTAM relay
   and the FAA service with no key, a bad key and no network.
7. **Maps**: offline pack status and the cycle date; display mode auto at sunset; sectional opacity; framing a NOTAM from the
   briefing on a rotated map and on an iPhone.
8. **OTA**: an update downloads at launch and runs only after the next cold start; none is applied during a recording.

## What I1d does

- **Settings** (`ui/shell/LiveSettings.tsx`, `settingsServices.ts`): the Log's settings button opens Settings over the log
  with its pages (Aircraft & Pilot and their editors, the night landing sheet, Offline Maps, Disclaimers). Services are the
  real ones: user database, keychain (FAA NOTAM key), the aviation databases' cycle and attribution, telemetry toggle, the
  remote config status, chart packs. The display mode is one value in one place (the text storage the map reads), shared by
  Settings and the Layers column. A region change restarts the live app on the new region from the launch state (the map
  recentres, sources reload, Settings closes); the databases are open already, only the region differs.
- **Chart packs** (`ui/shell/chartPacks.ts`): the CAAI CVFR chart (`israel-cvfr`), CAAI aerodrome diagrams (`il-diagrams`)
  and FAA airport diagrams (`us-diagrams`) on `ChartPackService` over the documents folder; Settings drives the first two.
  Developer setting "allow unpublished" is off in this build.
- **Airport diagrams overlay** (`ui/map/useAirportDiagrams.ts`): the overlay controller on the pack source (FAA diagrams
  on demand or from an installed pack, CAAI from the installed pack), kept in step with the region, the Layers switch and the
  remote kill switch (the Israel overlay's only), fed by the camera. Drawn by the map's existing diagram layers.
- **U4c mounts**: the US flight plan from the Log (`usPlanner.ts`; the route line is the app navigation's, the camera fits
  the plan through `mapFrameRequest`), the PIREP and winds aloft sections in the airport column (layers `pireps` and
  `windsAloft`, loaded by the airport column loader with the same per-airport request guard as the NOTAM list), the CVFR chart
  sheet on a map tap. `sections/parts.tsx` is gone: its helpers live in `sections.tsx`.
- **Map taps** (`ui/map/mapTap.ts`): the Israel chart first (nearest symbol within 26 pt: an aerodrome opens the airport column,
  a reporting point the chart sheet; else the airspaces under the finger), then the airport and weather dots. This was not
  wired at all before: an airport could not be opened from the map.
- **Alerts runtime** (Track B, #74) mounted by `alertsBinding.ts`: proximity and Israel services on the real databases and
  NOTAM feed, ownship fixes in, the notices and the Israel banner out, the TFR list read while the TFR layer is on.
- **Haptics**: `expo-haptics` (new package) behind `adapters/haptics.ts`: warning for a raised alert and for a recording that
  starts with the microphone off or with an error, success for a clean start and for End Recording, light for the strip
  cells (Layers, NRST, Brief), the Layers switches and segmented choices. Swift's six call sites, no others.
- **Official CAAI CVFR chart** (`ui/map/useOfficialChart.ts`, `domain/map/israel/officialChart.ts`): an installed
  `israel-cvfr` pack is the Israel base raster (`mbtiles://` source below every flight layer) and the vector CVFR layers it
  duplicates are hidden (closures and the point tap targets stay; routes, altitude labels, airspace fills and runways are off
  by default and still toggleable), as `IsraelChartOverlay.setOfficialChartPresent`. Following a download, an update or a
  removal while the map is open. CI has no pack installed, so the raster itself is a device check (item 10).
- **Strip callbacks**: the GPS-denied notice opens the system Settings page of the app.
- **Capture routes** with no SwiftUI reference (RN only, not gated): `usplan`, `chartsheet`, `chartairspace`, `aloft`,
  `alerts`.
