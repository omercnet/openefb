the nearest/search columns (U4a) follow in later PRs. Screens read their data through hooks over Zustand slices

## Swift differences

- `printfFixed`: `String(format: "%.Nf")` rounds an exact binary half to even (348.5 -> "348"); `toFixed` would give 349.
  Used for every `%.1f` and `%03.0f`, in the strip and in the footer's NRST distance and bearing. A tie is read from the exact
  decimal expansion (`toFixed(100)`), never from a floating-point multiply (`0.35 * 10` is exactly 3.5, yet 0.35 is below the
  tie); a test compares 30,001 values with an exact BigInt oracle.
- `clockText` uses `Intl.DateTimeFormat` in the given IANA zone (`formatToParts`, `hourCycle: 'h23'`; Swift `Calendar` +
  `TimeZone`). Run in Jest on Node (V8) only; Hermes ships the same `Intl` surface but it has not been run there.
- `predictionsOn` reads through a reader function instead of UserDefaults; strings follow `NSString.boolValue`.
- `ViewThatFits(in: .vertical)` for notices + NEXT is `FitsOrScrolls`: it measures the natural height against the given
  one and switches to a `ScrollView` only on overflow (a permanent scroll view re-rasterised the NEXT text on web).
- `AltitudeTape` label widths are estimated (6.4 pt per glyph, as the spike did) instead of measured.
- "GPS available" in the NRST cell is derived from `GpsStatus` (`lost` with no age); Swift reads `AppState.gpsAvailable`.
  The only visible difference is before the first fix (NONE in Swift, NO GPS here).
- Panel captions: SwiftUI `minimumScaleFactor(0.8)` is `adjustsFontSizeToFit` on native; react-native-web has none, so the
  caption measures an invisible copy and scales the font.
- The Layers switches are RN `Switch`: the native UISwitch on iOS; on web and Android the off track is `#B9BABE` (sampled
  from the reference). The segmented control is drawn (no dependency).
- The GPS cell's `minimumScaleFactor(0.7)` is computed (`monoFitScale`, the face is monospaced so no measuring is needed) and
  the NRST cell uses the same function. Each Layers segment is a button labelled with its group ("Display mode, Day") and
  `selected`: an `accessibilityLabel` on a non-accessible container is not spoken by iOS.
- Toggle rows expose role `switch` and `accessibilityState.checked`; Swift's extra spoken "On"/"Off" value on the panel
  toggles is not repeated (the screen reader already speaks the state).
- The strip ignores `showsFlightLog` (in Swift the container swaps layouts: U5); `FlightLogHeader` takes `showsNextTime`
  and `onClear` so the U5 full-width header can reuse it.
- JS-only guards (no Swift equivalent): `clockText` shows `---` for a non-finite time (Infinity at 0 kt) or a missing hour or
  minute instead of throwing or printing `00:00`, and an unknown IANA zone falls back to the device zone (Swift
  `TimeZone(identifier:) ?? .current`); `printfFixed` returns `nan` / `inf` like C instead of throwing; `FitsOrScrolls` ignores
  a box that has not been measured yet (two `onLayout` events arrive in either order); the footer swallows a throwing or
  rejecting `zoomTo` / `recenter` (and resets the zoom stepper) so an unready map cannot crash from a control; the stopping
  record button is `disabled` for accessibility (Swift marks nothing); a screen-reader step of the opacity slider snaps to a
  whole percent and ignores unknown actions.
- Swift behaviour preserved, for the owner to decide (safety relevant): with a stale GPS fix the NOW readouts dash and speak
  ", stale", but the leg progress "x / y NM" and its spoken text (`FlightLogRows.swift:294-306`), the off-route and altitude
  cautions (`FlightLogRows.swift:438-441`) and the NEXT nearest row (`FlightLogStrip.swift:624-627`) keep their last numbers.
  Also preserved: a paused recording's button is labelled "Resume recording" but does nothing (`RecordingOverlayView.swift`
  `RecordButton`: `default: break`). Neither was changed.

## Line height (shared token change, `src/ui/tokens.ts`)

`lineHeight()` returned the natural text height rounded to the nearest 0.5 pt on every platform. SwiftUI sizes a `Text` to its
natural height rounded up to the pixel grid (0.5 pt on the 2x iPad). RN iOS also ceils to that grid, but when the explicit line
height is above the font's natural one it applies a baseline offset ((line height - natural) / 2, `RCTApplyBaselineOffset`) and
the line box grows by that offset, so the ceil lands half a point higher: the 12.0 pt line of an 11 pt label measured 12.5 pt in
the iOS capture of main (every NEXT and NOW band was 0.5 pt too tall, the header 1 pt, and the U2 airport column ended 4.5 pt
low; measured band by band against the Swift capture at 2x). The rule is now per platform, each measured on the CI
simulator or emulator (run 43102552494 against main's run 43085625067), strip SSIM against the Swift references:

| Platform                | Rule                                                                                                      | map    | night  | airport | layers |
| ----------------------- | --------------------------------------------------------------------------------------------------------- | ------ | ------ | ------- | ------ |
| iOS (before)            | natural, nearest 0.5 pt                                                                                   | 0.9428 | 0.9483 | 0.8209  | -      |
| iOS                     | natural minus 0.01 pt (below the natural height RN adds no offset; the ceil lands on SwiftUI's grid line) | 0.9858 | 0.9856 | 0.8853  | 0.8872 |
| Android (before)        | natural, nearest 0.5 pt                                                                                   | 0.9904 | 0.9907 | 0.9813  | -      |
| Android, iOS rule tried | natural minus 0.01 pt                                                                                     | 0.9846 | 0.9847 | 0.8577  | 0.9111 |

The iOS rule is a large gain on iOS and a loss on Android: with the old rule every airport row sat within 1 dp of the reference
(row by row, ink runs against the Swift capture), with the iOS rule the whole column was 1 to 2 dp high. So the iOS rule is iOS
only and Android keeps the old rule. react-native-web, which has no pixel grid, gets the natural height rounded up to the 0.5 pt
grid (the Layers web render went from 0.857 to 0.908 with that alone). `tokens.test.ts` pins the three rules.

Evidence that SwiftUI uses the rounded-up natural height: in the Swift capture of the Nearest column (artifact
`scenario-captures` of Swift CI run 43054183844, `screens/ipad-nearest.png`) a row is 30.5 + 4 + 16.5 + 4 + 19.5 pt of text plus
16 pt of padding = 90.5 pt, rule to rule 91.5 pt, as measured; the 13 pt captions in `reference/ipad-layers.png` are 14.5 pt
(natural 14.144) where nearest-rounding gives 14.0.

Known limit: a natural height just above a grid line (13 pt SF, `systemFootnoteSemibold`, 15.509 pt) lands on the lower line
(15.5) where SwiftUI ceils to 16.0; the old rounding gave 15.5 too. The SF ratio (1.193) is an estimate, so a margin tighter
than 0.01 pt would risk the baseline offset for the other SF roles. The iOS airport interim floor (0.80) is gone: 0.8853 is
above the 0.85 target.

## Review decisions

- `FlightLogData` is flat plain data (navigation fields, ownship numbers, epoch ms, IANA zone); flown codes and every view
  string are derived on render, as the Swift computes them in `body`.
- Search writes `appStore.setStripColumn('search')` directly (as Swift writes `appState.stripColumn`); the other strip
  callbacks are `actions` in the slice, default no-ops.
- NEXT row accessibility follows the Swift literally: the ident `Text` carries the spoken line and testID, the big time and
  the data line are hidden from accessibility.
- The footer's NRST spoken extras (runway, private use, military, PPR, NOTAM closure) are optional fields on `NrstEntry`;
  U4a's `entryExtras` supplies them.
- The footer has `following` and `recenter` beyond zoom: Swift swaps ZOOM + for RECENTER after a pan. The fixture keeps
  `following: true`, so the reference renders unchanged.
- Data ages need a clock: `layers.now` (epoch ms), fed by I1.
- Airport diagrams default on in the Layers fake (AirportDiagramOverlay default when the key was never written); the row is
  below the fold of the reference.
