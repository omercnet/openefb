## Swift differences

- `printfFixed`: `String(format: "%.Nf")` rounds an exact binary half to even (348.5 -> "348"); `toFixed` would give 349.
  Used for every `%.1f` and `%03.0f`, in the strip and in the footer's NRST distance and bearing. A tie is read from the exact
  decimal expansion (`toFixed(100)`), never from a floating-point multiply (`0.35 * 10` is exactly 3.5, yet 0.35 is below the
  tie); a test compares 30,001 values with an exact BigInt oracle.
- `clockText` uses `Intl.DateTimeFormat` in the given IANA zone (`formatToParts`, `hourCycle: 'h23'`; Swift `Calendar` +
  `TimeZone`). Run in Jest on Node (V8) only; Hermes ships the same `Intl` surface but it has not been run there.
- `predictionsOn` reads through a reader function instead of UserDefaults; strings follow `NSString.boolValue`.
- `ViewThatFits(in: .vertical)` for notices + NEXT is `FitsOrScrolls`: it measures the natural height against the given
  one and switches to a `ScrollView` only on overflow (a permanent scroll view re-rasterised the NEXT text on web).
- `AltitudeTape` label widths are estimated (6.4 pt per glyph, as the spike did) instead of measured.
- "GPS available" in the NRST cell is derived from `GpsStatus` (`lost` with no age); Swift reads `AppState.gpsAvailable`.
  The only visible difference is before the first fix (NONE in Swift, NO GPS here).
- Panel captions: SwiftUI `minimumScaleFactor(0.8)` is `adjustsFontSizeToFit` on native; react-native-web has none, so the
  caption measures an invisible copy and scales the font.
- The Layers switches are RN `Switch`: the native UISwitch on iOS; on web and Android the off track is `#B9BABE` (sampled
  from the reference). The segmented control is drawn (no dependency).
- The GPS cell's `minimumScaleFactor(0.7)` is computed (`monoFitScale`, the face is monospaced so no measuring is needed) and
  the NRST cell uses the same function. Each Layers segment is a button labelled with its group ("Display mode, Day") and
  `selected`: an `accessibilityLabel` on a non-accessible container is not spoken by iOS.
- Toggle rows expose role `switch` and `accessibilityState.checked`; Swift's extra spoken "On"/"Off" value on the panel
  toggles is not repeated (the screen reader already speaks the state).
- The strip ignores `showsFlightLog` (in Swift the container swaps layouts: U5); `FlightLogHeader` takes `showsNextTime`
  and `onClear` so the U5 full-width header can reuse it.
- JS-only guards (no Swift equivalent): `clockText` shows `---` for a non-finite time (Infinity at 0 kt) or a missing hour or
  minute instead of throwing or printing `00:00`, and an unknown IANA zone falls back to the device zone (Swift
  `TimeZone(identifier:) ?? .current`); `printfFixed` returns `nan` / `inf` like C instead of throwing; `FitsOrScrolls` ignores
  a box that has not been measured yet (two `onLayout` events arrive in either order); the footer swallows a throwing or
  rejecting `zoomTo` / `recenter` (and resets the zoom stepper) so an unready map cannot crash from a control; the stopping
  record button is `disabled` for accessibility (Swift marks nothing); a screen-reader step of the opacity slider snaps to a
  whole percent and ignores unknown actions.
- Swift behaviour preserved, for the owner to decide (safety relevant): with a stale GPS fix the NOW readouts dash and speak
  ", stale", but the leg progress "x / y NM" and its spoken text (`FlightLogRows.swift:294-306`), the off-route and altitude
  cautions (`FlightLogRows.swift:438-441`) and the NEXT nearest row (`FlightLogStrip.swift:624-627`) keep their last numbers.
  Also preserved: a paused recording's button is labelled "Resume recording" but does nothing (`RecordingOverlayView.swift`
  `RecordButton`: `default: break`). Neither was changed.

## Line height (shared token change, `src/ui/tokens.ts`)

`lineHeight()` returned the natural text height rounded to the nearest 0.5 pt. SwiftUI sizes a `Text` to its natural height
rounded up to the pixel grid (0.5 pt on the 2x iPad). RN iOS also ceils to that grid, but when the explicit line height is
above the font's natural one it applies a baseline offset ((line height - natural) / 2, `RCTApplyBaselineOffset`) and the
line box grows by that offset, so the ceil lands half a point higher: the 12.0 pt line of an 11 pt label measured 12.5 pt in
the iOS capture of main (every NEXT and NOW band was 0.5 pt too tall, the header 1 pt, and the U2 airport column ended 4.5 pt
low; measured band by band against the Swift capture at 2x). Native now gets the natural height minus 0.01 pt: below the
natural height RN adds no offset, and the ceil lands on the same grid line as SwiftUI. react-native-web has no pixel grid and
gets the rounded-up height itself. The rule applies to every type role on both native platforms; on Android the line box is
ceiled to whole pixels, which is the same 0.5 dp grid at the 2x density of the capture emulator.

Evidence that SwiftUI uses the rounded-up natural height: in the Swift capture of the Nearest column (artifact
`scenario-captures` of Swift CI run 43054183844, `screens/ipad-nearest.png`) a row is 30.5 + 4 + 16.5 + 4 + 19.5 pt of text plus
16 pt of padding = 90.5 pt, rule to rule 91.5 pt, as measured; the 13 pt captions in `reference/ipad-layers.png` are 14.5 pt
(natural 14.144) where nearest-rounding gives 14.0. The Layers web render went from 0.857 to 0.908 and the map strip from
0.9795 to 0.9819 with this change alone. Not yet verified on iOS or Android (first CI run of this PR).

Known limit: a natural height just above a grid line (13 pt SF, `systemFootnoteSemibold`, 15.509 pt) lands on the lower line
(15.5) where SwiftUI ceils to 16.0; the old rounding gave 15.5 too. The SF ratio (1.193) is an estimate, so a margin
tighter than 0.01 pt would risk the baseline offset for the other SF roles.

## Review decisions

- `FlightLogData` is flat plain data (navigation fields, ownship numbers, epoch ms, IANA zone); flown codes and every view
  string are derived on render, as the Swift computes them in `body`.
- Search writes `appStore.setStripColumn('search')` directly (as Swift writes `appState.stripColumn`); the other strip
  callbacks are `actions` in the slice, default no-ops.
- NEXT row accessibility follows the Swift literally: the ident `Text` carries the spoken line and testID, the big time and
  the data line are hidden from accessibility.
- The footer's NRST spoken extras (runway, private use, military, PPR, NOTAM closure) are optional fields on `NrstEntry`;
  U4a's `entryExtras` supplies them.
- The footer has `following` and `recenter` beyond zoom: Swift swaps ZOOM + for RECENTER after a pan. The fixture keeps
  `following: true`, so the reference renders unchanged.
- Data ages need a clock: `layers.now` (epoch ms), fed by I1.
- Airport diagrams default on in the Layers fake (AirportDiagramOverlay default when the key was never written); the row is
  below the fold of the reference.

- Tests (86 in `src/ui/log`: logic 35, `LogStack` 31 counting each `it.each` row, render counts 10, `LogScreen` 5, clock 5):
  `FlownEntryActionTests` 5 of 5 ported against the plain `LogbookEntry` from `src/data/models.ts` (the Swift builds SwiftData
  objects; identity checks became `toBe` on the same object) plus one extra; the pure text, ordering and duration functions with
  their accessibility strings; render tests for the reference state, every action, Now hidden when idle, active plan, stale ETE,
  countdown/paused/stopping, Sign and Review rows, flights without entries, manual entries, 30 flights, long names, Night; render
  counts that prove each section re-renders only for its own fields (checked by mutation: a whole-slice subscription or the
  clock added to any section fails them); the local clock.
- Data: the Log reads navigation, recording, ETE, GPS availability and the last fix (`ownshipFix`) from the strip's `flightLog`
  slice and `nextIdent(nav)` from `flightLog/logic.ts`, so the two cannot drift; the `log` slice holds only the flights and the
  logbook entries, and `logActions` (openMap, openSettings, openPlanner, addEntry, openFlight, openEntry, deleteEntry) the
  callbacks, all no-ops until I1 wires navigation. Totals are derived from the entries, as `LogbookViewModel` does. The two
  slices follow different conventions on purpose: `logActions` is separate, so replacing the `log` state cannot drop a callback
  (the `flightLog`, `footer` and `layers` slices keep theirs inside the data and must be fed with `setState(partial)`).
- Clock: Swift's `LogStackView` ages the last fix once a second with a `TimelineView` and works the Now row's staleness out from the
  raw fix. `useNow(1000)` (`log/clock.tsx`) does the same with an interval that only the Now row subscribes to, stops while the app
  is not active and takes the time at once on resume; `NowProvider` fixes it for tests and captures. It is a second clock next to
  `flightLog.nowMs` (the scenario clock fed by I1): the Log follows Swift, so a scenario run that fakes time must also fake the
  fix timestamps. `ownshipFix` must be null before the first fix and I1 must re-emit `isStationary` on a stationary notice that has
  no position (`LocationService.swift:177`), or the Log hides the ETE 5 s after the aircraft stops.
- Capture route: `src/app/log.tsx` wraps `LogScreen` in `LogReference`, which supplies fresh reference stores (no navigation,
  recording 5 s, GPS ok, no flights) and a fixed clock; a plain `LogScreen` follows the shared slices. Defaults are the reference
  fakes, not an idle state: I1 must feed every field it uses (a field it forgets keeps its fake value).
- Decimal hours use `printfFixed` (an independent review caught the first version, which read a tie from `seconds / 3600 * 10`:
  180 s printed "0.0" where `String(format: "%.1f")` prints "0.1"). Durations round half to even like `Duration.formatted`.
- Deviations: deleting an unsigned draft is only a screen-reader action (`deleteEntry`); a visual swipe gesture needs a gesture
  library, which I1 decides. The totals row wraps instead of switching to a vertical stack (`ViewThatFits`). The glass toolbar
  buttons are a flat fill with a shadow tuned to the reference, not a blur material. `minimumScaleFactor` is
  `adjustsFontSizeToFit` (no web equivalent). The route arrow (U+25B8) is in no bundled face, so iOS and Android fall back to a
  system face (a headless Linux Chromium draws a box; the reference state has no route). Dates and times are en_US 12-hour ("Nov 11, 2026 at 4:36 PM"); Swift's `Date.formatted` follows the device locale and its 24-hour setting, so this is revisited with the Hebrew and locale pass (U6). The `/log` route unmounts the map (the root layout is a `Slot`) while Swift keeps `MapContainerView` mounted under the Log (`ContentView.swift`: tearing it down would orphan an active recording): the app shell (U5/I1) must show the Log as an overlay, the route is for the fidelity gate only. The 'signed entries are locked' rule is enforced where the UI reaches `deleteEntry` (`deleteUnsignedEntry`); I1's implementation must re-check `isConfirmed` like Swift's `delete(_:)`. A non-finite duration is skipped in the totals instead of turning the sum into `--- h` (JS-only guard); a non-finite ETE shows `ETE ---`. The glass buttons are night-aware (`paperSecondary` and a dark shadow). The iOS 26 narrow no-break space before
  AM/PM is a plain space. The signature, book and check icons are not in the reference and are sized by estimate.
- Fidelity: `log` joins the gate (route, `LAUNCH_SCREENS`, both capture scripts, where it waits a fixed time like `sheet` because
  it has no map and keeps its logcat, `reference/ipad-log.png`). Local web render: strip 0.989, whole frame 0.993; every element is
  within 1 pt of the reference. The strip metric (the leading 400 pt) is wrong for this full-width screen: its lower half is empty
  paper, so a blank Log scores 0.867 on the strip against a 0.85 floor (probed with fake screenshots through `compare.mjs`; erasing
  only the REC time still scores 1.0). `fidelity-thresholds.json` therefore takes a per-screen `"metric": "frame"`
  (`compare.mjs` gates `r[metric].ssim`), used for the iOS `log` entry: target 0.93, interim 0.90 until the first CI measurement
  (a blank frame scores 0.85, the web render 0.993). On Android only the strip can be compared (the screen is 800 dp wide against
  the 1032 pt reference); a blank scores 0.7955 against the 0.80 floor, so it still fails the gate. `search` has an iOS interim of
  0.75 for the unmeasured keyboard region (see U4.md). `tests/config/fidelityGate.test.ts` checks that every gated screen has a
  route, a launch entry, both capture-script entries, a reference and consistent floors.
