## Design

- AppState is not ported. LocationService owns a plain `OwnshipState` (the nine AppState fields it wrote, same
  defaults) and reports a copy through `onChange`. `appState.updateActiveRouteProgress(now:)` became the `onFix(nowMs)`
  hook; whoever ports AppState/ActiveRoute wires both.
- The Swift `updates:` seam (AsyncThrowingStream factory) became `LocationSource.subscribe(request, listener)`;
  "the stream threw" is `listener.onError`. A Swift stream ending without error stopped tracking; the port has no
  normal end (live sources never end), so only errors restart.
- Timers (no-fix grace, restart backoff) go through an injectable `Timers`; tests use Jest fake timers instead of the
  Swift poll-until-true harness. `start()` while tracking is a no-op (Swift started a second task).
- TrackRecorder takes `TrackStore` (D4), `PhaseDetector` and `VerticalSpeedEstimator` (L4) interfaces plus `newId`.
  The store is async, so `stop()` is async: it waits for queued fixes, then closes the last marker. Fixes are
  serialised through a promise queue (the Swift actor did this). `FlightPhase`, `TrackPoint` and `PhaseMarker` are
  defined in trackRecorder.ts; L4/D4 should move them to their own modules when they land.
- Units follow CoreLocation in the port (m, m/s, degrees, negative = invalid) so conversions match Swift exactly.
  Altitude rounding uses half-away-from-zero (Swift `rounded()`), not `Math.round`.

## Adapter gaps vs CLLocationUpdate (verify on device, I3)

- No stationary flag: expo-location does not report CoreLocation's pause. The adapter sets
  `pausesUpdatesAutomatically: false`, so updates never pause and the flag is never sent. GPSStatus keeps the
  stationary branch for when a source can report it.
- `authorizationRestricted` cannot be told apart from denied (expo reports both as `denied`); restricted shows as
  denied. `locationUnavailable` is not reported; a watch error surfaces as `streamFailed`.
- Location Services off is sent as `authorizationDeniedGlobally`, a denied permission as `authorizationDenied`; an
  undetermined permission sends nothing. In all three the subscription stays idle: unlike CoreLocation, it does not
  resume by itself when the user changes Settings. The app must re-subscribe (stop/start LocationService) after
  `requestPermission` or on return to foreground.
- Background updates use one TaskManager task (`kanaf-location`) shared by all background subscribers; the first
  subscriber's activity type wins (LocationService asks `otherNavigation`, TrackRecorder `airborne`). The task is
  defined at module scope, so `src/adapters/location.ts` must be imported at app start.
- iOS: Swift used CLBackgroundActivitySession with When In Use. Whether expo's `startLocationUpdatesAsync` needs
  Always on iOS is to be checked on device; if it does, a start failure reaches `onError` (GPS stopped) and the
  caller must ask `requestPermission('background')` first.
- Android: the foreground service notification text is `FOREGROUND_SERVICE_NOTIFICATION`; no custom 96x96 icon
  (`androidForegroundServiceIcon` unset, the app icon is used). `killServiceOnDestroy: true` matches the Swift
  session ending with the app.

## Config

- Usage strings now match efb-212.xcodeproj (`INFOPLIST_KEY_NSLocationWhenInUseUsageDescription`,
  `INFOPLIST_KEY_NSLocationAlwaysAndWhenInUseUsageDescription`); the Swift target has no
  `NSLocationAlwaysUsageDescription`, so `locationAlwaysPermission: false` removes it. The previous shared string was
  not the Swift one.
- UIBackgroundModes stays `location` + `audio` (existing `withOnlyLocationAudioBackground` mod, matching Info.plist).
- Android permissions listed explicitly: ACCESS_FINE_LOCATION, ACCESS_COARSE_LOCATION, ACCESS_BACKGROUND_LOCATION,
  FOREGROUND_SERVICE, FOREGROUND_SERVICE_LOCATION (plus the existing FOREGROUND_SERVICE_MICROPHONE).
- SelfTestScreen keeps its own spike task (`kanaf-spike-location`); not changed here.

- Swift quirk kept (CodeRabbit finding): LocationService uses location.altitude for VSI even when verticalAccuracy is negative; the adapter encodes a missing altitude as 0 with verticalAccuracyM -1, so VSI can spike on such fixes. Revisit on device in I3.
