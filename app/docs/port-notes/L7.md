# L7 port notes (prediction)

- Ported: `PredictedEvent.swift` (types), `AirspacePredictor.swift` (engine + `PredictionStabilizer`), `PredictionService.swift` (mappers + update/clear/cache). Swift tests ported: AirspacePredictorTests (16), PredictionServiceTests (14: US and Israel mappers, update/debounce). Plus 3 extras (rounding, ids, cache reuse). Not ported: `ViewModelTests/PredictionRowsTests` (view model, UI ticket) and the RegionTests prediction case (AppState).
- Distance: the only distance in the engine is the circle containment check. Swift used `CLLocation` WGS84 distance; TS uses the core haversine. All Swift expectations (e.g. circle entry in 210..225 s) pass unchanged, so no WGS84 precision was needed and no test was loosened.
- `PredictionService` takes injected interfaces instead of AppState / GRDB / CLLocation: `PredictionAirspaceSources` (US and Israel airspace queries), `VerticalSpeedSource` (the L4 `VerticalSpeedEstimator` plugs in here; tests use a zero fake), `PredictionState` (region, track, groundSpeed, predictedEvents). The Israel database is opened by the caller; a throwing source yields no volumes (Swift `try?`).
- `IsraelAirspaceInput` is a structural stand-in for `IsraelAirspace` (Data/IsraelAviationModels.swift); when the Israel models land it should be replaced by (or adapted from) that type. Only the fields the mapper reads are included.
- Rounding: `assumptionText` reproduces `%03.0f` (half to even) and `Double.rounded()` (half away from zero) explicitly. Number grouping is a regex, not Intl, so it is identical on Hermes.
- Airspace ids: Swift `UUID.uuidString`; TS ids are plain strings, so volume ids read `us-<id>`.
- Events are plain objects; Swift's custom Equatable becomes `predictedEventsEqual`; `id` becomes `predictedEventId(e)`.
