## Differences

- `@Generable` Foundation Models schema is plain interfaces; the on-device model call is an adapter concern.
- Israel models (reporting point, route segment, altitudes) are structural subsets in `types.ts` marked `TODO(L3)`;
  record shapes (track point, transcript, phase marker) are subsets marked `TODO(D)`.
- Swift computed properties (`id`, `seconds`, `isEmpty`, leg accessors) are exported functions.
- Swift `.rounded()` rounds halves away from zero; a helper reproduces it (Math.round differs for negative halves).
- `loadBundled` (open bundled DB, `try?` to nil) is not ported: it swallows errors silently and opening the database is an
  adapter job. `loadCVFRDebrief` takes injected async sources and lets errors propagate.
- Israel bounding box (29.0-33.6 N, 33.8-36.2 E) is a local constant in the loader, `TODO(region)`, until Region is ported.
- `FlightMetadata.description` formats the date with an injectable formatter (default `Intl` en-US medium/short; Swift used
  the device locale, so the text can differ, e.g. "at" between date and time).
- Prompt length counts use code points, Swift counts grapheme clusters (equal for the ASCII prompts built here).
- `polylineLengthNm` is a private helper in `cvfrDebrief.ts`, `TODO(L1)`.
- DebriefRecord JSON uses sorted keys, like Swift's `.sortedKeys`.

- CVFR facts are cut at 1,800 characters with `prefix`, possibly mid-value, as in Swift (review finding declined for parity).
