## Swift behaviour preserved

- A sectional pack without `cycleEffective` never expires (Swift BUG pinned by `sectionalPackWithoutCycleNeverExpires`).
- No antimeridian handling in bounds; latitude is not clamped in `boundsAround`.
- A pack that MapLibre marks complete with missing resources reads partial, not ready; a failed pack reads not downloaded.
- Redownload = delete, then download for the same layer and region.

## Platform differences (MapLibre RN v11 OfflineManager vs MLNOfflineStorage)

- The engine port is `createPack / listPacks / resume / pause / delete`. RN `createPack` takes the style as a string (we pass
  the reduced style JSON, no temp files, so Swift's `offline-styles/` directory and `writtenStyleURLs` cache are an
  in-memory cache), and metadata as an object (the context). RN creates the pack inactive; the service resumes it, as Swift did.
- RN has no `invalid` pack state, no global tile limit call that is needed here (`setTileCountLimit` is not called:
  unlimited by default is to be confirmed on device), and no whole-storage byte counter: `storageUsedBytes` is the sum of the
  packs' completed bytes (Swift used `countOfBytesCompleted`, which also counts the ambient cache).
- Progress and errors arrive through per-pack listeners given at creation. After an app restart the listeners are gone
  until a pack is touched; `useOfflineMaps` refreshes on mount, and pause/resume/delete re-read the list. Live progress for
  packs created in an earlier session needs `OfflineManager.addListener` for each id: UNVERIFIED, check on device.

## JS-only guards

- Per-layer isolation: a failing layer does not stop the other layer's download; creation errors set `lastError`, a corrupt
  base style also sets it and is rethrown after the other layers were attempted.
- `refresh` coalesces overlapping calls into one follow-up read (latest state wins). A failing `listPacks` keeps the previous
  packs and sets an error, so a failed read never reads as "no packs". Packs with foreign or malformed metadata are ignored,
  never deleted.
- `delete` removes the row at once; a failed engine delete reports and the follow-up refresh restores the row. A refresh
  already in flight when a delete starts can briefly re-list the pack before the follow-up read removes it.
- Non-finite or negative status numbers read 0; a pack whose status call fails reads inactive with no progress.
- Size text approximates `ByteCountFormatter(.file)` (decimal units, KB whole, MB+ one decimal); Swift has no test for it.

## Tile-failure handling

`TileFailureTracker` (L1) and the controller's `noteTileError` / `noteTileLoadedFromNetwork` were ported in M1. M3 supplies the
signals: error log lines that look like failed requests (`isTileFailureLog`) and "map fully rendered" as the recovery signal.
RN v11 has no per-tile event, so this is a heuristic and UNVERIFIED on a device; the patterns need tuning from an offline run.

## Not done

Debug-only `OfflineBlockingURLProtocol` (the offline verification harness) is not ported; use airplane mode or the emulator
network switch for the device check. `OfflineMapsView` is a functional compact list, not a pixel port: its fidelity capture
needs a Swift reference (see M1.md, Fidelity), and the screen is wired into Settings by I1. Create/resume/delete against the
real native module is not exercised by Jest; it needs the device check above.

## Offline labels (bundled glyphs)

Fixes the regression recorded in `M1-israel.md`: text labels (street names, Israel chart points, altitudes, airspace and
closure text) used the remote OpenFreeMap glyph endpoint, so they disappeared offline while geometry still drew.

- Asset: `assets/glyphs/Noto Sans Regular/{0-255,1280-1535,8192-8447}.pbf`, 188,506 bytes in total (Basic Latin and Latin-1
  including the degree sign, Hebrew U+0500-05FF, general punctuation). Noto Sans is SIL OFL 1.1; the files are the OpenFreeMap
  font set's pre-built ranges (the Hebrew range contains the Noto Sans Hebrew fallback glyphs, ids 1424 to 1524). Not bundled
  on purpose: Latin Extended (256-511, 127 KB), Arabic and other scripts. A character in an unbundled range is simply not drawn.
- `domain/map/glyphs.ts`: the stack and range table, `localGlyphsUrl`, `withLocalGlyphs`, `fontStacksUsedBy`, and
  `emptyGlyphRangePbf`. Every other range of the 256 is written as an empty, valid PBF at install time (about 253 tiny files
  generated in code), because a missing range file fails the glyph request for the whole label.
- `adapters/glyphInstall.ts`: copies the bundled ranges to `Paths.document/glyphs` once (marker file `.version`, written last),
  returns the `file://.../{fontstack}/{range}.pbf` template. `MapScreen` waits for it (milliseconds after the first launch) and
  falls back to the remote endpoint only if the install fails (then it logs, and labels need a network again).
- Tests: the style's glyphs URL is local and never remote; every `text-font` used by the base style and by the US and Israel
  registries is a bundled stack; the bundled ranges cover Latin, the degree sign, Hebrew and punctuation; the street pack
  style keeps the local glyphs; the files exist and stay under 250 KB.
- Not verified on a device: that MapLibre Native accepts `file://` glyph templates on both platforms (it supports `file://`
  and `asset://` sources; Android `file://` for glyphs is expected to work but needs the offline capture run), and Expo's
  `File.write(Uint8Array)` for the generated files.
- Shared files touched: `app/assets/glyphs/**` (new binary assets), `app/metro.config.js` (`pbf` added to `assetExts`),
  `app/src/ui/map/surfaceModel.ts` (`styleFor` takes the glyphs URL), `MapSurface.tsx` (`glyphsUrl` prop), `MapScreen.tsx` and
  its test. No `app.config.ts` change: assets are bundled by Metro through `require`.
