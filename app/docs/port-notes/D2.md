# D2 port notes: schema, migrations, repositories

## Design

- `src/data/migrations/001_initial.ts` holds the v1 SQL as a TS string (plan 3.4 says `.sql`; a TS module needs no Metro
  asset config and loads unchanged in Jest). `PRAGMA user_version` is the schema version; `migrate(db)` applies each newer
  migration in its own transaction together with its version bump, refuses a database newer than the app, and is idempotent.
- Columns are the Swift property names in snake_case (`fuelBurnGPH` -> `fuel_burn_gph`, `departureICAO` -> `departure_icao`).
  Dates are epoch ms, UUIDs text (lower case when generated here; the D3 importer normalises Swift's upper case),
  booleans 0/1 with CHECK constraints, enums stay strings (unknown values are stored as is, like Swift).
- `vSpeedsData` / `nightLandingEntriesData` keep their Swift names but hold JSON text (the Swift blobs are JSON). Unreadable
  JSON reads as nil / `[]`, like `try?` in Swift. Night landing dates inside the JSON are epoch ms (Swift encodes seconds
  since 2001; D3 converts).
- No foreign keys: the Swift models link by UUID string (`aircraftProfileID`, `flightID`, ...) and never enforce it.
- List order is a repository convention (Swift orders in `@Query`): aircraft and pilots oldest first, flight plans by last
  use, flights and logbook newest first.
- `SettingsRepository.getOrCreate` mirrors the app's "fetch first, insert if none" use of `UserSettings`.

## Swift behaviour preserved

- An unknown `regionRaw` reads as the default region but is not repaired in storage.
- `medicalClass`/`certificateType` accept any string; the enum accessors return null for unknown values
  (`certificateTypeOf` expects the raw value `"private"`, not the Swift case name `privatePilot`).

## Not ported in this ticket (with reason)

- `DatabaseManager.swift`: wraps the aviation database; belongs to D5 (aviation DB access).
- `ModelContainerFactory.swift` and the SwiftData container tests (`appStyleStoreReopensThroughVersionedSchemaAndMigrationPlan`,
  `legacyStoreReopensThroughTheAppContainerFactory`, `factoryStoreReopensWithTheLegacyStyleContainer`,
  `inMemoryFactoryContainerRegistersEverySchemaV1Model`, `migrationPlanHasOnlySchemaV1AndNoStages`,
  `schemaV1ListsTheSixModelTypesTheAppRegisters`): SwiftData plumbing. Replaced by `migrate.test.ts` (six tables, version,
  idempotence, upgrade, rollback). The data-level intent (a seeded store reopens with all rows) is in `repositories.test.ts`.
- `aircraftVSpeedsRoundTrip` Swift-encoder specifics, and `FlightPlanRecord.toFlightPlan()` / `init(from:)`: need the
  `FlightPlan`/`Waypoint` domain types, which are L2. `flightPlanRecordToFlightPlan` ports with L2.
- View-model cases in LogbookEntryTests (`formatDuration*`, `createFromRecording*`, `confirmedEntryIsLocked`): LogbookViewModel
  is U7/L6. Likewise LogbookViewModelTests, FlownEntryActionTests, FlightPlanViewModelTests, IsraelFlightPlanViewModelTests,
  IsraelLSAPlannerTests, RegionTests.
- FlightPersistence*/FlightRecovery tests drive the recording services against these models plus the recording DB; they port
  with L4/D4 on top of `flightRecordRepository`/`logbookRepository`.
