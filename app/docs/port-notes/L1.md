# L1 port notes (core domain)

## PR 1: geometry, polygon, region, units

- Distance: `distanceNm` is haversine on a 3440.065 NM sphere (spike choice). Swift `CLLocation.distance(from:)` uses the WGS84 ellipsoid, so results differ by up to about 0.3 percent. Not preserved; no Swift test compares exact values.
- `fromMetarTime`/`timeAgoShort` take reference/now epoch ms instead of reading the clock.
- Swift `Region` is an enum with methods; TS uses a string union plus free functions (`regionContains(r, c)`, etc.).
- Not ported (later PRs or other tickets): RegionStore (SwiftData; data layer), AppState-dependent RegionTests (layer toggling, region switching, first-launch hint, weather view model, METAR altimeter parsing -> METAR PR), LiveNavigationProgressTests distance use (route ticket).
- Old paths `domain/geo.ts` and `domain/types.ts` remain as re-exports.

## PR 2: freshness, METAR visibility, tile failure tracker

- `DataFreshness`, `OverlayStaleness`: `now` is a required parameter (epoch ms); durations are seconds. `warnBeforeExpiry` is inlined as the chartCycle 7 day rule.
- `TileFailureTracker` is an immutable value with free functions instead of a mutating struct.
- Not ported here: the METAR/WeatherViewModel/WeatherService cases of `MetarVisibilityTests` (decodedVisibility etc.) and the METAR altimeter-parsing RegionTests; they need the weather service and view model (other tickets). `TAFValidity` goes with the TAF PR.
