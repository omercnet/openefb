# L1 port notes (core domain)

## PR 1: geometry, polygon, region, units

- Distance: `distanceNm` is haversine on a 3440.065 NM sphere (spike choice). Swift `CLLocation.distance(from:)` uses the WGS84 ellipsoid, so results differ by up to about 0.3 percent. Not preserved; no Swift test compares exact values.
- `fromMetarTime`/`timeAgoShort` take reference/now epoch ms instead of reading the clock.
- Swift `Region` is an enum with methods; TS uses a string union plus free functions (`regionContains(r, c)`, etc.).
- Not ported (later PRs or other tickets): RegionStore (SwiftData; data layer), AppState-dependent RegionTests (layer toggling, region switching, first-launch hint, weather view model, METAR altimeter parsing -> METAR PR), LiveNavigationProgressTests distance use (route ticket).
- Old paths `domain/geo.ts` and `domain/types.ts` remain as re-exports.

## PR 2: freshness, METAR visibility, tile failure tracker

- `DataFreshness`, `OverlayStaleness`: `now` is a required parameter (epoch ms); durations are seconds. `warnBeforeExpiry` is inlined as the chartCycle 7-day rule.
- `TileFailureTracker` is an immutable value with free functions instead of a mutating struct.
- Not ported here: the METAR/WeatherViewModel/WeatherService cases of `MetarVisibilityTests` (decodedVisibility etc.) and the METAR altimeter-parsing RegionTests; they need the weather service and view model (other tickets). `TAFValidity` goes with the TAF PR.

## PR 3 (in progress): TAF validity

- `tafValidUntil(raw, now)` ports `TAFValidity.validUntil`. The "TAF past its valid period reads expired" WeatherRefreshFailureTests case needs the weather view model and is not ported here.

## PR 4 (local): EFBError info

- `core/errorInfo.ts` adds `errorId`, `errorDescription`, `errorSeverity` over the spike's `AppError` union (`domain/errors.ts` is unchanged). Swift ids print Doubles as "3600.0"; TS prints "3600". `chartExpired` date uses `toLocaleDateString('en-US', medium)` in the device time zone like Swift's DateFormatter.

## PR 5 (local): models, enums, landable filter

- `core/types.ts` gains the Types.swift enums as string unions with the Swift raw values (persisted): `OwnershipType` is `'public'|'private'|'military'`, `CertificateType` uses `'private'`. Computed properties become free functions (`gpsUpdateInterval(p)`, `tfrTypeDisplayName(t)`, ...).
- `core/models.ts` ports AviationModels structs as plain interfaces keeping Swift field names (`latitude`, `longitude`, ...) so DB rows map directly. Dates are epoch ms, UUIDs plain strings; the domain generates no ids, so `makeFlightPlan`, `makeWaypoint`, `makeWeatherCache` require `id` (and `createdAt`/`fetchedAt`). `Airport` equality is ICAO-only via `airportsEqual`. `age`/`isStale`/`isActive`/`isExpired` take `nowMs`.
- `InterruptionGapReason` is a discriminated union; Swift's synthesized Codable JSON shape is left to the data layer. `AirspaceGeometry` keeps its custom Swift JSON shape (`decode/encodeAirspaceGeometry`).
- `LandableAirportFilter` ported with the Swift tie rule (first longest runway wins). `NearestAirportEntry` assertions in `militaryIsFlaggedMilNotPvtAndStillListed` are not ported (nearest-airport service ticket).
- Not ported: AppState+Navigation (UI state), DesignTokens/Disclaimers/DisplayMode/Interaction/RemoteConfig/DataRefreshScheduler/Protocols/ActiveRoute/AppState (other tickets per port-map).

- `fromMetarTime` does not validate field ranges: Swift lenient Calendar rolls them over and the port keeps that.
