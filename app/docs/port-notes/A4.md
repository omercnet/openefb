# A4 SecretStore notes

- Swift KeychainStore has no tests (port-map: 0 cases); the TS tests are new and cover the adapter option mapping and the fake.
- Service `quartermint.efb-212.faa-notam-api`, accounts `client_id` and `client_secret` (NotamService.swift). Accessibility
  `AFTER_FIRST_UNLOCK_THIS_DEVICE_ONLY` matches kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly.
- CORRECTION (CodeRabbit review): expo-secure-store does NOT read Swift items in place. Its iOS queries require
  kSecAttrGeneric and also look up suffixed services, and the Swift items have neither; get/remove on a Swift-written item
  miss it (remove would leave the credential in the Keychain). The service/account names are kept identical so a native
  lookup can find the items. D3 (importer) must read the Swift items with a native Keychain query (class genericPassword,
  service + account, no generic attribute), write them through this SecretStore, then delete the originals. Not done here:
  it needs native code and device verification (I3).
- Swift `string(forAccount:)` returned nil on any failure; the adapter `get` maps errors to null. Swift `setString`/`removeValue` throw; the adapter rejects.
- The layout doc's keychain table is empty (simulator export failed with -34018), so names come from Swift source.
