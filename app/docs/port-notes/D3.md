# D3 port notes: Swift data importer

Code: `src/data/import/`. Tests: `tests/data/import/swiftImport.test.ts` against `tests/fixtures/swift-store-v1/`.
Plan section 4 steps 0, 1, 3 and the keychain; step 2 (recording.sqlite) is D4.

## Design

- `runSwiftImport(target, legacy)` runs three steps (`swift-store`, `user-defaults`, `keychain`), each recorded in
  `migration_state` (migration 002). A re-run skips completed steps and retries failed ones. A failing step does not stop
  the others. Nothing deletes legacy files. No legacy input marks the step complete ("no legacy store"): fresh installs
  and Android.
- Step 1 is table-driven (`ENTITIES`): source column, target column, decode kind. The source `Db` is opened read-only by the
  caller (expo-sqlite attached by path on device; a read-only node handle in Jest). Target writes are one transaction.
  Rows use `INSERT OR IGNORE`, so a re-run adds nothing and never overwrites edits; settings are only imported when the
  target has no settings row.
- Decoding: Core Data REAL seconds since 2001 -> epoch ms; UUID blobs (16 bytes) -> lower-case text; UUID text columns lower
  cased (Swift writes upper case, so links between rows keep matching); booleans 0/1; the two JSON blobs (`ZVSPEEDSDATA`,
  `ZNIGHTLANDINGENTRIESDATA`) are read as UTF-8 text. Night landing `date` values inside the JSON are converted from seconds
  since 2001 (Swift's default `Date` coding) to epoch ms.
- Corrupt input: a store without `Z_PRIMARYKEY`, with an unknown model (newer schema), or missing a mapped table/column
  fails with `UnsupportedStoreError` and imports nothing. A row with an unreadable id is skipped, an unreadable optional
  value (bad JSON, wrong type) is dropped to null; both are listed in `result.skipped`. A truncated `-wal` imports whatever
  SQLite can still read.
- UserDefaults: the adapter passes the decoded `io.omer.efb` domain as a plain object (the fixture is a binary plist; the
  test decodes it with a small reader in `tests/support/swiftFixtures.ts`). Known keys (grep of efb-212: AppStorage and
  `UserDefaults.standard`, plus `israel.routeNetwork.<uuid>`) go to `app_preferences` as JSON text; unknown keys and the
  debug switches `simulateDatabaseFailure` are ignored. Keys whose values are not plain strings, numbers, booleans or string
  arrays are ignored.
- Keychain: reads service `quartermint.efb-212.faa-notam-api`, accounts `client_id` / `client_secret` through a
  `LegacySecretReader`, writes through `SecretStore`, reads back, and deletes the legacy item only after the read-back
  matches. A value already present in the new store wins. A failure leaves the legacy item and marks the step failed so
  retry moves it.

## Needs an on-device check (no fixture possible)

- The keychain step: the simulator build has no keychain entitlement (errSecMissingEntitlement), so service/account names
  come from the code only, and the native `LegacySecretReader` is unproven. The items use
  `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`; an item written by another build/access group may not be readable.
- Reading the real `default.store` path, and the WAL when the store was not closed cleanly.

## Interface assumptions (ports are not on main yet)

`LegacySecretReader` and `SecretStore` are declared structurally in `import/keychain.ts` (`read/delete(service, account)`,
`get/set(key)`); the real ports must stay assignable to them or the two small interfaces get replaced by imports.
SecretStore key names `faa-notam.client_id` / `faa-notam.client_secret` are a proposal for the NOTAM adapter to adopt.

## Swift differences

None. Two deliberate choices: ids are lower case (Swift stores `uuidString` upper case in text columns), and settings from
the Swift store are not imported over an existing row.

## Tests

Fixture equality (closed and live copies, field-level for aircraft, pilots, settings; counts and links for the rest),
idempotent re-run, edit preservation, read-only source, empty store, future schema, missing column, unreadable id/JSON,

no-overwrite, orchestration (resume after failure, fresh install). 29 new cases; none dropped (no Swift test exists for
the importer).
