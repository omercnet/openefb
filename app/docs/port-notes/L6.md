# L6 port notes: currency + logbook rules

Source: `efb-212/Services/CurrencyService.swift` -> `src/domain/currency/currency.ts`.
Tests: 21 of 21 `CurrencyServiceTests` cases ported (all names kept).

## Differences

- `now` is a required parameter (epoch ms) instead of defaulting to `Date()`. Tests use a fixed `now`, which removes
  the sub-millisecond drift the Swift tests tolerated (for example "exactly 30 days" was 29.999 days in Swift).
- Swift used `Calendar.current` (device timezone, DST-aware day arithmetic). The port uses UTC: a day is 86,400,000 ms
  and months are added in UTC with end-of-month clamping. Behaviour differs only across a DST change within the window
  (up to 1 hour), which can shift a boundary day. Not preserved because the domain layer is platform-free.
- INTENTIONAL DIFFERENCE FROM SWIFT, owner decision Q3=A (2026-11-10): a medical whose expiry time has passed reads
  `expired` immediately. Swift truncated the day count toward zero, so 0 to 24 hours past expiry read `warning`. The
  warning window before expiry (0 to 30 whole days remaining, exactly at expiry still `warning`) is unchanged. Flight
  review status goes through the same comparison, so it changes the same way. Tests added for just before, exactly at,
  1 ms after and 1 hour after expiry.
- `CurrencyStatus` is a string union with the Swift raw values.
- Non-finite (NaN) expiry or review timestamps read `expired`; Swift Dates cannot be NaN (JS-only guard).
- Night landings dated after `now` still count (Swift filters only `date >= cutoff`); kept for parity, review finding declined.
