# T05: Offline maps (dashboard ticket T05; beads efb-zfm.5; audit finding F6 in docs/DESIGN.md)

## Problem
Every base map (efb-212/Resources/base-style.json: OpenFreeMap vector "openmaptiles", Esri "satellite", OpenTopoMap "terrain",
FAA "vfr-sectional" raster, z8-12) is online-only. Offline in the air you get a plain background under the flight layers, and the
pilot can't tell beforehand what will work. Settings claims charts are cached. MapService.addSectionalOverlay still looks for an
unused `sectional.mbtiles`.

## Files you own
- New: efb-212/Services/OfflineMapService.swift (+ protocol), efb-212/Views/Settings/OfflineMapsView.swift (or similar).
- SettingsView.swift: Charts section only.
- LayerControlsView.swift: add a small "Offline: ready / partial / none" line and the chart cycle. Re-read the file before
  editing; T11 adds one toggle row there and T07 restyles it later.
- MapService.swift: only remove the dead MBTiles path (addSectionalOverlay / readChartExpirationMetadata) if you replace it.
  T06 owns camera/ownship/airport-query code there.

## Change
1. **Region downloads.** Use MapLibre offline packs (`MLNOfflineStorage`, `MLNTilePyramidOfflineRegion` with the bundled
   base-style.json URL).
   - A pilot picks a region from a list of FAA sectional areas (San Francisco, Los Angeles, …; hardcode bounding boxes for the
     contiguous US sectionals, the source is public) or "Current map view".
   - Zoom ranges: sectional z8-12; street z5-13; terrain/satellite optional and off by default, since they are large.
   - Show an estimated size before download, progress, pause/cancel, delete, and storage used.
2. **Respect tile terms.** Satellite (Esri) and OpenTopoMap have usage limits; don't bulk-download them by default. Note the
   limits in a short comment and in Settings.
3. **Status.** Expose "offline ready" for the current map view (all required tiles present for the visible region at the
   active style's zoom range). Show it in the layer panel as "Offline: ready / partial / not downloaded".
4. **Chart cycle.** Compute the current 56-day sectional cycle date (FAA publishes sectional effective dates on a 56-day
   cycle; derive it from a known anchor date and verify against the FAA site). Show "Sectional cycle: valid to <date>". When
   a downloaded pack predates the current cycle, mark it expired and offer re-download. Never show an expired sectional as
   current (amber "Expired" badge).
5. **Copy.** Settings text must state exactly what is offline (airport DB, downloaded regions, cached FAA charts / PDFs) and
   what needs the internet (weather, TFRs, NOTAMs, PIREPs).

## Acceptance
- Unit tests: cycle-date computation across a boundary; region size estimate; status derivation (ready / partial / none /
  expired) from a mocked pack list.
- Visual proof: a throwaway XCUITest downloads a SMALL region (a few km around KPAO at a limited zoom range so it finishes
  quickly), then shows the layer panel status. Screenshots in docs/design/screenshots/T05/ and dashboard deliverables.
- Also verify offline: after downloading, turn off the network if possible. If not possible in the simulator, use
  `MLNNetworkConfiguration` or point the style at an unreachable host in a test build, and show the map still renders the
  downloaded tiles. Document how you verified it.
- Full unit suite green.
