# T09: In-app copy pass (dashboard ticket T09; beads efb-77r.8; improve-app phase 6)

Use the `made-to-stick` skill (.claude/skills/made-to-stick), with one hard rule: standard aviation terms and abbreviations (CTAF,
METAR, TAF, AGL, MSL, NOTAM, TFR, PIREP, VFR, IFR, MVFR, LIFR, NRST, TRK, GS, VS, etc.) are never rewritten into plain language.

## Scope
Every user-facing string:
- onboarding;
- empty, error and stale states;
- alerts and confirmation dialogs;
- Settings;
- the beta banner (F14: shorten; after first dismissal it lives in Settings > About);
- layer panel captions;
- the disclaimers required by PRD.md §12.

## Rules
- Each error says what happened and how to fix it, and doesn't blame the pilot.
- Remove happy-talk. Cut words by half where it keeps the meaning.
- One term per concept across the app (e.g. "Nearest" vs "NRST", "Recording" vs "Record").
- Check the PRD's required disclaimers ("not for primary navigation", etc.) are present and placed where they're seen, not hidden.

Record the key messages per surface in docs/POSITIONING.md `## Key Messages` (surface | message | status). Create the file from
the improve-app template headings if it is missing.

## Acceptance
- A table of before/after strings in docs/POSITIONING.md.
- Screenshots of onboarding and two error states in docs/design/screenshots/T09/.
- Full unit suite green. Update any test that asserts exact copy only if the copy is the behaviour under test.
